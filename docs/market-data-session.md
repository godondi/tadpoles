# Fauxnance candles and internal booking sessions

The backend candle DTO omits null fields. Synthetic daily bars can therefore arrive without `volume`. The chart accepts missing or null volume as unavailable, normalizes it to null for display/deduplication, and continues to validate dates, positive OHLC values and their high/low relationships.

Fauxnance can return fresh quotes with `marketState: "unknown"`. For internally booked orders, `TradingSession` uses the instrument asset class for a scheduled fallback: U.S. equities require a verified NYSE, NYSE Arca or NASDAQ core session (09:30 inclusive through 16:00 exclusive, with weekends, holidays and early closes accounted for); FX is open Sunday 17:00 through Friday 17:00 Eastern; crypto is continuously open. U.S. equities use `America/New_York` (including DST), and the checked-in exchange calendar covers **2026 only**; extend and verify it before another year. Unsupported venues/asset classes and other unrecognized states fail closed. For FX, missing or `unknown` status and generic exchange states (`closed`, `pre`, `post`) use the OTC weekly schedule; `halted` and other unsupported states remain closed. Explicit provider closed/pre/post states continue to take precedence for equities.

The published equity schedules are [NYSE hours and calendars](https://www.nyse.com/trade/hours-calendars) and [Nasdaq's 2026 trading calendar](https://www.nasdaqtrader.com/trader.aspx?id=Calendar). These are scheduled-session fallbacks for internal bookings, not live market-status feeds. Operations must disable trading for unscheduled closures or halts that the provider does not report.

The provider's original `unknown` state stays in quote evidence; successful evaluation reasons identify use of the scheduled session. Preview, admission and worker execution all use the same rule. All price, currency, freshness, metadata and resource checks still apply, including the configured maximum quote age. A cached provider quote may report `stale: false` yet fail its timestamp check; the application must not treat that flag as permission to use an expired price.

The internal demo catalog defaults to a 1800-second maximum quote age to accommodate the reported twenty-minute provider refresh cadence. Operations can set a stricter age per instrument; the editor/API accept 1–1800 seconds. Existing policies are preserved on startup and must be changed through Operations, retaining their revision and audit trail. Quotes marked stale, older than the selected age, or future-dated beyond the clock-skew allowance remain ineligible. Quote age is measured against the provider's quote timestamp; the separate metadata timestamp is retained and must not be missing or too far in the future, but an older metadata timestamp does not override a fresh quote timestamp.

If Fauxnance explicitly returns `meta.stale: true`, order checks return `QUOTE_STALE` with a message explaining that the provider must update before the order can be reviewed again. This applies even within the configured age allowance. Absent freshness, missing metadata timestamps, unsupported spread sources and blank quote sources have separate explanatory messages under `QUOTE_METADATA`. Refreshing the application requests another provider observation; it cannot force the upstream cache to refresh.
